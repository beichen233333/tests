# 完整行为复刻：四阶段执行计划

## 总目标

以用户提供的原始 `libastraeoffline.so` 为唯一基准，恢复其可观察行为：相同请求输入、游戏状态和表数据下，复刻库产生相同的响应对象、存档变化、UI/流程状态变化及错误处理。

“完全相同”在本项目中定义为**可观察行为等价**，不承诺重建原项目逐字 C 源码或生成与原始机器码逐字节相同的 ELF。逆向资料显示原 ELF 保留 DWARF、符号与反汇编，但不含原始 C 源码正文。

## 阶段一：原版基线与调用链审计（当前阶段）

目标：建立不可漂移的原版证据基线，识别复刻工程的阻塞点与缺口。

范围：
- 校验原始 ELF 哈希、架构、SONAME、DT_NEEDED、动态导出符号；
- 固化 126 个导出 ABI 分类、结构布局、390 个文本函数符号与 333 个 DWARF 函数签名；
- 固化 93 个请求协议、116 个响应协议、359 个 Managed Wire 类型；
- 固化 9 份嵌入数据 JSON、46 个表名及 4578 条表记录；
- 对 39 个 Hook 区分 29 个 trampoline Hook 与 10 个 direct replacement Hook；
- 审计当前自动启动与 `local_request` 安装路径，生成逐协议、逐 Hook、逐 Store API 清单。

完成标准：所有清单可由 `scripts/phase1_baseline_audit.py` 重复生成；关键原始证据一致；未把 schema/route 映射误报为业务语义等价。

## 阶段二：业务后端语义恢复

目标：恢复原版业务状态机、存档和协议处理，不再只以 schema 默认值生成响应。

范围：
- 逐个对照 44 个 `store_*` API 的反汇编、数据结构、校验条件、事务与回滚路径；
- 逐个审计 93 个 Request handler，区分真正业务实现、只返回默认响应、无状态请求和未完成逻辑；
- 恢复 AccountLogin 所需初始状态、角色/阵容/库存/通知/任务/解锁数据；
- 解析 9 份数据表的主键、关联、奖励、开放条件和规则；
- 为每种请求建立输入状态、请求、响应、输出状态的差分用例。

完成标准：每个 Store API 和请求协议均有实现证据与测试；关键存档状态与原版相同；未知请求和失败分支也符合原版行为。

## 阶段三：运行时、IL2CPP、Hook 与 UI 行为恢复

目标：让复刻库在目标游戏进程内按原版时序接管消息并完成 Managed Response 回调。

范围：
- 重建 ELF constructor / worker 的初始化顺序及线程附着生命周期；
- 正确实现 10 个 direct replacement 和 29 个 trampoline Hook，不把 `has_trampoline=false` 误判为禁用；
- 对两个缺失 DWARF 签名的替换回调恢复真实 ABI；
- 恢复 `local_request`、`read_packet`、`wire_read`、`wire_respond` 的真实消息路径；
- 恢复 UI、首日、通知、战斗、加载、原生菜单等 Hook 的业务副作用，而不是仅做透传；
- 为补丁写入、指令重定位、并发执行、GCHandle、GC write barrier 和回调线程增加目标 ARM64 验证。

完成标准：39 个 Hook 的目标、ABI、行为和调用时序均有证据；所有支持路径不依赖猜测的 trampoline 或方法签名。

## 阶段四：全链路集成与行为等价验证

目标：证明替换库在目标环境中能够完成全部游戏流程。

范围：
- 使用 Android NDK 构建 `arm64-v8a` 并验证 ELF ABI、导出符号、依赖及页大小兼容；
- 原版/复刻版同状态请求回放，逐字段比较 Response 与存档差异；
- 在匹配版本的目标游戏中验证启动、开屏、登录、账号初始化、首日流程、大厅、角色、商店、任务、战斗、活动、存档重启；
- 将每次真机问题关联到 logcat、tombstone、Hook 计数和原始目标指纹。

完成标准：端到端流程无卡死/崩溃；协议与状态差分达到约定覆盖；不存在仅凭主机测试通过就认定 Android 等价的结论。

## 当前阶段边界

阶段一只建立基线并定位代码级缺口，不启用未经验证的运行时 Hook。阶段二开始恢复业务语义，阶段三再恢复运行时接管，阶段四做目标设备验证。
